# Swift

Use `crap.py swift PROJECT SOURCE...` and `mutation.py swift PROJECT`. Both checks require macOS and report a run failure elsewhere. Install Xcode's Swift and LLVM tools and Muter manually; missing tools fail with an install hint. Lizard installs automatically outside the project unless `--no-install` is supplied.

The CRAP check runs `xcrun swift test --enable-code-coverage` and copies SwiftPM's LLVM JSON coverage report, which combines all test binaries. Swift has no branch records, so the result explicitly labels the measured proportion as **region coverage** and applies the same 90% requirement. Region coverage does not measure an absent `else` path and is weaker than branch coverage.

Mutation requires a configured `muter.conf.yml` (create it with `muter init`). Muter 16 writes no code snippets, so actionable mutants may have no diff or function name. Muter creates `<project>_mutated` next to the project: put the isolated copy inside its own disposable parent directory. Alternatively, `--overlay` creates and cleans up the copy and disposable parent automatically, keeping Muter's sibling directory away from the real project. A replacement mutation command receives the absolute expected report path in `WORKFLOW_REPORT_FILE`.

`duplication.py swift PROJECT SOURCE.swift...` returns `unverified: language not supported` with exit 1. Mutation accepts `--previous-evidence DIRECTORY`; Muter's `--files-to-mutate` option reruns whole changed files. Muter reports only file base names, so outcomes are bound to a source file by unique base name; ambiguous names force a full run, and the result says so and reports that fallback. Unchanged non-actionable outcomes are labelled as reused. Tests, engine/configuration or language-module changes force a full run; damaged evidence fails closed. Tool versions are recorded in evidence. See the [shared contract](../quality-tools.md).

Arguments after `--` replace the test or mutation command. A direct `swift test` or `xcrun swift test` override must include `--enable-code-coverage`. After the test run, the same command with `--show-codecov-path` queries the report location without rerunning tests; this preserves release configurations, custom scratch paths, and all other SwiftPM settings. A wrapper command must write its LLVM JSON report to `WORKFLOW_COVERAGE_FILE`. Reports and evidence are preserved; `--timeout-ms` defaults to 3,600,000. Verified with Swift 6.4 and Muter 16 on macOS.
